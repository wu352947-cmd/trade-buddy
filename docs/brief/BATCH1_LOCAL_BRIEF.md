## 已确认决策（必须遵守）

- 产品名：**Trade Buddy**（原创品牌，禁止出现 TradingView 名称、Logo、图标、专有插画或复制其前端源码）。
- 数据：首期免费档；没有 key 时也必须能渲染图表。
- 市场：美股、A 股、港股、期货与指数。
- 运行：**本批只做本地运行，不上云服务器，不写 Docker / Caddy / 云部署脚手架，不需要登录鉴权。**
- 配色：默认绿涨红跌（`intl`），设置内可一键切换红涨绿跌（`cn`）。色值按规划 Design Tokens（绿 `#16B981`、红 `#F2485B` 或等价 token）。
- 定位：仅研究与模拟。代码与 UI 严禁真实交易、券商 SDK、下单按钮、杠杆。用户未成年。
- **禁止爬取 TradingView 或其私有 API。禁止读取、打印或提交任何已有 token**（尤其不要碰 `/workspace/stonequant-data/.tushare_env`）。不要提交 `.env`、密钥、`node_modules`、构建产物。

## 本批范围（Batch 1–2 + 能用的图表，按本地简化）

目标：执行 `npm install && npm run dev` 或 `pnpm install && pnpm dev` 后，打开本地地址就能看到专业深色五区看盘终端，中间是**真实渲染出来的 K 线图**（不是占位框）。

### 1. 工程与设计系统

- 采用规划推荐栈，可按本地版适度简化：
  - 前端：**Next.js（App Router）+ React + TypeScript + Tailwind CSS**
  - 图表：**KLineChart**（Apache 2.0，npm 包 `klinecharts`）
  - 可用 pnpm workspace / 简单 monorepo（`apps/web`、`packages/*`），但**不要为了完整 monorepo 而做 gateway、PostgreSQL、Redis、登录、Docker**。
- 落地 Trade Buddy 原创设计 tokens：深色默认、浅色可切（浅色可先做 token，UI 至少深色完整可用）、绿涨红跌默认 / 红涨绿跌切换。
- 原创 Logo（规划中的「双柱伴行」方向即可）和一套够用的原创工具栏 SVG 图标（不必一次做满 28 个，但画线工具、周期、图表类型、自选等核心图标要有）。
- 根目录 `.gitignore`：忽略 `node_modules`、`.next`、`dist`、`.env`、`.env.local`、`.turbo`、缓存等。
- 更新根目录 `README.md`：中文说明如何本地安装与启动、数据源是什么、没有 key 时会用样本数据、如何配置可选 API key、合规声明（仅研究、非 TradingView 官方产品）。

### 2. 五区工作区壳子（对照 `docs/ui-refs/main-workspace.png` 等，模仿布局与专业感，不抄像素和商标）

桌面默认布局（请按宽屏 1600×900 认真排版，信息密集、细分割线、专业深色终端风格）：

1. **左侧画线工具栏**：趋势线、水平线、射线、矩形、斐波那契、文字、十字/测量、橡皮擦/删除等（KLineChart Overlay 能做的优先做成能用的；做不到的可先图标占位，但至少 2–3 种能真正画到图上）。
2. **顶部栏**：Logo + 当前品种（代码与名称）+ 品种搜索入口 + 周期切换（至少 1D / 1W / 1M，若样本数据允许可加 60m）+ 图表类型（K 线必做，空心 K / 折线 / 面积尽量做）+ 指标入口 + 主题/涨跌配色切换。
3. **中间主图**：K 线 + 成交量副图 + 十字光标 + 缩放/平移 + 价格轴与时间轴。必须是 KLineChart 真实渲染，不能只放静态图。
4. **右侧栏**：默认 4 个市场分组的自选表（美股 / A 股 / 港股 / 期货与指数），点击切换主图品种；可附简要行情或涨跌；另可有品种详情/数据窗口（来源与延迟要标明）。
5. **底部面板**：可先做折叠式信息/数据窗口或研究笔记占位，默认较矮，把高度留给图表。

默认打开时就进入 `/` 或 `/chart` 工作区，**不要强制登录页**。搜索弹窗可以是简化版（能从自选/内置品种列表里搜代码或名称并切图即可）。

### 3. 指标（至少这些要能加到图上并看到结果）

- 主图：MA（或多条均线）、EMA、BOLL
- 副图：RSI、MACD
- 成交量默认显示
- 要能从顶栏/指标菜单开关，不要写死无法关闭

### 4. 数据层（本地适配器）

做一个清晰的数据适配层（例如 `packages/market-adapters` 或 `apps/web` 内的 server route / 本地模块）：

- **没有 API key 时必须用仓库内捆绑的样本 OHLC 数据渲染**，保证开箱即用。样本至少覆盖四个市场分组，每组若干代表性品种（例如美股 AAPL/MSFT/SPY/QQQ，A 股 600519/000001，港股 00700，期货或指数用指数/ETF 如 ES 或 SPX/NQ 的日线样本）。样本应是真实历史日线（至少 1–2 年），写明来源与日期，不要随机假数据。
- 若某个**有文档的免费 API** 无需 key 且条款允许，可作为可选实时/延迟日线来源；成功时优先用它，失败则回退样本。
- 需要 API key 的源（Polygon / Twelve Data / Finnhub / Tushare 等）一律做成**可选**，通过 `.env.local`（提供 `.env.example`，不要提交真实密钥）配置。没 key 就不要去请求。
- UI 上诚实标注：样本 / 延迟 / 日线 EOD / 免费源名称。不要伪装成交易所实时。
- **不要使用可能违反条款的非官方 Yahoo 图表接口。不要爬 TradingView。**

### 5. 本地运行（本批唯一运行方式）

- README 写清：安装 Node 版本、`pnpm install` 或 `npm install`，然后 `pnpm dev` / `npm run dev`，默认端口（如 3000）。
- 不需要 Docker，不需要数据库，不需要登录。
- TypeScript 与生产构建应能通过（`pnpm build` / `npm run build`）。

## 验收标准

1. 全新目录执行安装与 `dev` 后，浏览器打开即为深色专业看盘终端。
2. 主图能看到真实 K 线、成交量、十字光标，切换周期与自选品种会更新图表。
3. 能打开并看到 MA/EMA/RSI/MACD/BOLL 中的至少一个主图指标和一个副图指标。
4. 能切换绿涨红跌 / 红涨绿跌，K 线颜色跟着变。
5. 构建无 TypeScript / 打包错误。
6. 仓库干净：有合理 `.gitignore`，无密钥、无 `node_modules`、无 TradingView 商标资源。
